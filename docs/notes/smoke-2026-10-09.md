# Smoke test -- 2026-10-09 (post-fix, two runs)

Both runs below are **after** the root-cause fix for the ~146s fault-to-
detection delay (commits `e74055d`, `b0241b7`). Commits tested, head at
the time of both runs: `b0241b7` (`fix(core): health_state as an InfluxDB
tag fragmented a resource's series across the fault boundary`), on top of
every commit from `9b84a4e` (autonomous loop) through `62ef2be`
(`--concurrency=1` stopgap) on `feat/loop-week5`.

## Root cause (summary -- see commit b0241b7 for the full writeup)

`core/collector.py` tagged every InfluxDB point with `health_state`
(`healthy`/`degraded`/...). A tag change starts a new InfluxDB series, and
`health_state` flips the instant a fault lands. `core/influx.py`'s
`query_recent_window` ran a plain `from()|>range()|>filter()` with no
`group()`/`sort()`, so the one leftover `health_state=healthy` point from
just before the fault kept landing last in Flux's table-iteration order --
making `series[-1]` ("the latest reading", `ml/detectors/threshold.py`'s
`_last_values`) return that stale point instead of any of the real,
breach-worthy post-fault points sitting in the query's *other* table. The
stale point only aged out once it left the 120s lookback window --
confirmed via `DETECTOR_TRACE=1` and raw InfluxDB timestamps on a real run:
last `healthy` point at `10:07:20`, real data in the trace at `10:09:20`
(120s later, to the second), detection 30s after that (3 breaches at a 10s
tick -- the documented rule, working correctly throughout).

Fix: `health_state` is now a string field, not a tag (`core/collector.py`,
`core/influx.py`'s new `string_fields` param), and `query_recent_window`
explicitly sorts every signal's points by timestamp before returning them,
rather than trusting Flux's table order. Neither change touches
`ml/detectors/threshold.py` -- no threshold, fence, or breach-rule changed,
so no harness number in `docs/results/practice-run.md` is affected.

**Before**: fault-to-action-succeeded 146.81s / 146.78s (two runs, pre-fix).
**After**: 36.30s / 36.84s (below).
